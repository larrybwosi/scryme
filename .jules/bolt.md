## 2026-08-10 - [Parallelized Service Bookings and Writes in CreateOrderUseCase]
**Learning:** Sequential processing of dynamic booking creations (`bookingService.createBooking`) and downstream database updates (`transactionServiceItem.create` and `serviceBooking.update`) inside loops creates severe $O(N)$ blocking times. Parallelizing independent creations and batch-writing relation links concurrently using `Promise.all` collapses the execution profile down to a flat, resilient $O(1)$ concurrent execution block, significantly reducing latency on service order checkout paths.
**Action:** Always inspect service/checkout loops and parallelize independent booking registrations and relational database writes concurrently using `Promise.all`.
